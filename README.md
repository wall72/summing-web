# Summing Mobile

9x9 보드에 현재 숫자를 배치하고, 이웃한 숫자들의 합이 맞으면 타일을 지우는 브라우저 숫자 퍼즐 게임입니다. 설치나 빌드 없이 정적 HTML/CSS/바닐라 JS로 동작합니다.

**플레이:** https://wall72.github.io/summing-web/

## 게임 방법

- 보드는 9x9이고, 시작할 때 가운데 7x7 영역에 0~9 숫자가 무작위로 채워집니다. 바깥 테두리는 비어 있습니다.
- 화면 위쪽의 숫자 스트림(5개) 중 맨 앞 숫자가 지금 놓을 숫자입니다.
- 빈 칸을 눌러 숫자를 놓으면 스트림이 한 칸 당겨지고 새 숫자가 하나 추가됩니다.
- 놓은 칸 주변 8방향의 채워진 타일 숫자를 모두 더해서 `합 % 10` 이 놓은 숫자와 같으면, 놓은 타일과 그 이웃 타일이 모두 사라집니다. 채워진 이웃이 없으면 매치되지 않습니다.
- 점수는 `지운 타일 수 x 10` 이고, 보드를 전부 비우면 최종 점수가 `max(1000, 3000 - 이동 수 x 20)` 이 되도록 보너스를 받습니다. 적은 이동으로 클리어할수록 점수가 높습니다.
- 보드를 전부 비우면 승리(`Cleared!`), 81칸이 모두 차면 패배(`Game Over`)입니다.
- 끝나면 결과 화면이 표시되고, 이름을 입력하면 기록이 상위 기록(리더보드)에 저장됩니다. "익명으로 저장"도 가능합니다.
- **되돌리기:** 직전에 놓은 수 하나를 취소할 수 있고, 게임당 3회까지입니다. 보드, 스트림, 점수, 이동 수가 직전 상태로 돌아가며 감점은 없습니다. 되돌린 뒤 다시 놓을 때 스트림에 새로 붙는 숫자는 처음과 같아서, 되돌려서 숫자를 다시 뽑을 수는 없습니다. 이동 애니메이션 중과 게임이 끝난 뒤에는 되돌릴 수 없습니다.
- **힌트:** 지금 놓을 숫자가 매치되는 빈 칸 하나를 깜빡여 알려 줍니다(여러 곳이면 가장 많이 지워지는 칸). 게임당 3회, 감점은 없습니다. 매치되는 칸이 없으면 횟수가 차감되지 않습니다. 이동 애니메이션 중과 게임이 끝난 뒤에는 쓸 수 없습니다.

## 주요 기능

- 세로/가로 화면에 대응하는 반응형 레이아웃
- 타일 배치, 매치, 제거 애니메이션
- `localStorage` 에 진행 중인 게임 자동 저장 및 복원 (새로고침해도 이어하기, 종료된 게임은 결과 화면 복원)
- 게임 종료 시 사용자명 입력 (최대 12자, 다음 게임에 기억)
- 최대 20개까지 저장되는 리더보드: 기본은 기기별 로컬 저장, `config.js` 에 Google Apps Script URL 을 설정하면 서버(Google 스프레드시트) 공유 리더보드 (GitHub Pages/로컬/자체 서버 어디서나 동일, 서버 장애 시 로컬로 대체. 설정 방법: `server/apps-script/README.md`)
- 손상된 저장 데이터는 검증 후 폐기하고 새로 시작
- 키보드 조작과 스크린 리더 지원 (칸이 `button`, 칸별 `aria-label`, `aria-live` 상태 안내)
- 되돌리기(직전 1수, 게임당 3회, 새로고침 후에도 유지)
- 힌트(매치되는 칸 표시, 게임당 3회, 새로고침 후에도 유지)
- 최고 점수 표시, 게임 중 새 게임(확인 대화상자)과 기록 보기
- 한국어 UI
- PWA: 홈 화면에 설치하고 오프라인에서도 실행
- 단위 테스트 + Playwright E2E 테스트, GitHub Pages 자동 배포

## 로컬 실행

`index.html` 을 브라우저에서 바로 열어도 되지만, 로컬 서버로 여는 것을 권장합니다.

```bash
python3 -m http.server 8000
# 또는
npx http-server -p 8000
```

브라우저에서 `http://localhost:8000` 을 엽니다.

## 테스트

```bash
npm test                 # 단위 테스트 (Node 내장 러너, Node 18 이상)
npm ci                   # E2E 준비: 의존성 설치
npx playwright install chromium
npm run test:e2e         # Playwright E2E (모바일/데스크톱)
```

- 단위 테스트(`tests/logic.test.js`): 보드/스트림 생성, 매치·비매치 판정, 종료 상태 판정, 저장 데이터 검증, 리더보드 정렬
- E2E 테스트(`e2e/game.spec.js`): 새 게임 시작, 배치와 새로고침 후 복원, 매치 시 점수, 클리어 결과 화면과 기록, 손상된 저장 데이터 복구, 새 게임 확인 대화상자, 키보드 조작

## 배포

`master` 브랜치에 푸시하면 `.github/workflows/pages.yml` 이 단위·E2E 테스트를 실행하고, 모두 통과하면 GitHub Pages 에 배포합니다.
처음 한 번은 저장소 Settings → Pages → Source 를 **GitHub Actions** 로 설정해야 합니다.

```text
.
|-- index.html                    게임/결과 화면 마크업

|-- tests/                        node --test 용 단위 테스트
|-- e2e/, playwright.config.js    Playwright E2E 테스트
|-- .github/workflows/pages.yml   테스트 후 Pages 배포
|-- package.json
|-- LICENSE                       MIT 라이선스
|-- README.md
`-- CLAUDE.md                     Claude Code 작업 지침
```

## 제한 사항

- 되돌리기(Undo)는 직전 1수만, 게임당 3회까지. 힌트는 게임당 3회까지(칸 하나만 표시)
- 서버 리더보드는 선택 사항이며 `config.js` 에 URL 을 설정해야 동작함. 점수는 서버에서 재현 검증하지 않음(범위·일관성 검사만)
